= カスタムOpenTelemetryコレクター
:page-languages: [en, de, es, fr, ja, pt, zh]
:revdate: 2026-10-10
:page-revdate: {revdate}
:description: {admc-name}を設定して、クラスター内にデプロイされたカスタムOpenTelemetryコレクターに安全にテレメトリーデータを送信します。
:keywords: kubewarden、kubernetes、メトリクス、トレーシング、opentelemetry
:doc-persona: kubewarden-operator, kubewarden-integrator
:doc-type: HOWTO(操作方法)
:doc-topic: operator-manual、テレメトリ、メトリクス、クイックスタート

このガイドでは、クラスターにすでにデプロイされているOpenTelemetryコレクターにテレメトリーデータを送信するために{admc-short-name}を設定する方法を説明します。

クラスター内にlink:https://opentelemetry.io/docs/collector/[OpenTelemetry Collector]のインスタンスを1つだけデプロイする必要があります。

== 依存関係をインストールする

まず、OpenTelemetryコレクターの依存関係をインストールすることから始めます。

{admc-name}コンポーネントとコレクター間で暗号化された通信が必要です。安全な通信に必要なすべての証明書を管理するためにlink:https://cert-manager.io/[cert-manager]を使用できます。

OpenTelemetryコレクターのトレースは、link:https://www.jaegertracing.io/[Jaeger]インスタンスに送信されます。

{admc-short-name}スタックは、OpenTelemetryコレクターにメトリクスを送信します。
このメトリクスは、Prometheusエンドポイントとして公開されます。メトリクスは、その後Prometheusインスタンスによって収集され、データベースに保存されます。同じPrometheusインスタンスは、メトリクスを表示および使用するためのUIも公開します。

作成したリソースは、`kubewarden`ネームスペースで定義されるか、その存在が期待されます。そのため、ネームスペースを作成することから始めるべきです：

[source,console,subs="attributes+"]
----
kubectl create namespace {admc-namespace}

kubectl create secret docker-registry application-collection \
  --namespace {admc-namespace} \
  --docker-server=dp.apps.rancher.io \
  --docker-username=<your-username> \
  --docker-password=<your-token>
----

=== cert-managerとOpenTelemetryをインストールする

このようにしてcert-managerとOpenTelemetryオペレーターをインストールします：

[source,console,subs="attributes+"]
----
for ns in cert-manager open-telemetry; do
  kubectl create namespace $ns
  kubectl create secret docker-registry application-collection \
    --namespace $ns \
    --docker-server=dp.apps.rancher.io \
    --docker-username=<your-username> \
    --docker-password=<your-token>
done

helm install --wait \
  --namespace cert-manager \
  --set crds.enabled=true \
  --set global.imagePullSecrets=\{application-collection} \
  --version 1.21.2 \
  cert-manager oci://dp.apps.rancher.io/charts/cert-manager

helm install --wait \
  --namespace open-telemetry \
  --version 0.124.1 \
  --set global.imagePullSecrets=\{application-collection} \
  --set manager.collectorImage.tag=0.160.0-contrib \
  my-opentelemetry-operator oci://dp.apps.rancher.io/charts/opentelemetry-operator
----

{admc-short-name}コンポーネントとOpenTelemetryコレクター間の通信をmTLSを使用して設定します。

それを行うには、全体の公開鍵インフラストラクチャ (PKI) を作成する必要があります：

[source,yaml,subs="attributes+"]
----
# pki.yaml file
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: my-client-certificate
  namespace: {admc-namespace}
spec:
  dnsNames:
  - kubewarden.{admc-namespace}.svc
  - kubewarden.{admc-namespace}.svc.cluster.local
  issuerRef:
  kind: Issuer
  name: my-selfsigned-issuer
  secretName: my-client-cert
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: my-certificate
  namespace: {admc-namespace}
spec:
  dnsNames:
  - my-collector-collector.{admc-namespace}.svc
  - my-collector-collector.{admc-namespace}.svc.cluster.local
  issuerRef:
  kind: Issuer
  name: my-selfsigned-issuer
  secretName: my-server-cert
---
apiVersion: cert-manager.io/v1
kind: Issuer
metadata:
  name: my-selfsigned-issuer
  namespace: {admc-namespace}
spec:
  selfSigned: {}
----
マニフェストを適用します：
[source,console]
----
kubectl apply -f pki.yaml
----

=== Jaeger と Prometheus をインストールします

その後、トレースイベントを保存し、可視化するために https://www.jaegertracing.io/[Jaeger] をインストールします。

[source,console,subs="attributes+"]
----
kubectl create namespace jaeger

kubectl create secret docker-registry application-collection \
  --namespace jaeger \
  --docker-server=dp.apps.rancher.io \
  --docker-username=<your-username> \
  --docker-password=<your-token>

helm upgrade -i --wait \
  --namespace jaeger \
  --version 2.57.0 \
  jaeger-operator oci://dp.apps.rancher.io/charts/jaeger-operator \
  --set global.imagePullSecrets=\{application-collection} \
  --set rbac.clusterRole=true

kubectl apply -f - <<EOF
apiVersion: jaegertracing.io/v1
kind: Jaeger
metadata:
  name: my-open-telemetry
  namespace: jaeger
spec:
  imagePullSecrets:
    - name: application-collection
EOF
----

OpenTelemetry のクイックスタートで Traefik をインストールした場合は、次の `Ingress` を使用して Jaeger クエリ UI を公開します：

[yaml]
----
kubectl apply -f - <<EOF +
apiVersion: networking.k8s.io/v1 +
kind:Ingress +
metadata: +
  name: my-open-telemetry-query +
  namespace: jaeger +
spec: +
  ingressClassName: traefik +
  rules: +
    - http: +
        paths: +
          - path: / +
            pathType:Prefix +
            backend: +
              service: +
                name: my-open-telemetry-query +
                port: +
                  number:16686 +
EOF
----

次に、メトリクスを保存し、可視化するために https://prometheus.io/[Prometheus] をインストールします。

[source,console,subs="attributes+"]
----
cat <<EOF > kube-prometheus-stack-values.yaml
prometheus:
  additionalServiceMonitors:
  - name: kubewarden
    selector:
    matchLabels:
      app.kubernetes.io/instance: {admc-namespace}.my-collector
    namespaceSelector:
    matchNames:
      - {admc-namespace}
    endpoints:
    - port: prometheus
    interval: 10s
EOF

kubectl create namespace prometheus

kubectl create secret docker-registry application-collection \
  --namespace prometheus \
  --docker-server=dp.apps.rancher.io \
  --docker-username=<your-username> \
  --docker-password=<your-token>

helm install --wait \
  --namespace prometheus \
  --version 92.1.0 \
  --values kube-prometheus-stack-values.yaml \
  --set global.imagePullSecrets=\{application-collection} \
  prometheus oci://dp.apps.rancher.io/charts/prometheus-operator
----

[NOTE]
====

Prometheus サービスモニターは、{admc-short-name} メトリクスを取得するために、`kubewarden` ネームスペースで実行されている OpenTelemetry コレクターをスクレイピングします。

====

== OpenTelemetry コレクターをインストールします

これで、`kubewarden` ネームスペースにカスタム OpenTelemetry コレクターをデプロイできます。

[source,yaml,subs="attributes+"]
----
# otel-collector.yaml file
apiVersion: v1
kind: ServiceAccount
metadata:
  name: my-collector
  namespace: {admc-namespace}
imagePullSecrets:
  - name: application-collection
---
apiVersion: opentelemetry.io/v1beta1
kind: OpenTelemetryCollector
metadata:
  name: my-collector
  namespace: {admc-namespace}
spec:
  mode: deployment # This configuration is omittable.
  serviceAccount: my-collector
  volumes:
  - name: server-certificate
    secret:
    secretName: my-server-cert
  - name: client-certificate
    secret:
    secretName: my-client-cert
  volumeMounts:
  - name: server-certificate
    mountPath: /tmp/etc/ssl/certs/my-server-cert
    readOnly: true
  - name: client-certificate
    mountPath: /tmp/etc/ssl/certs/my-client-cert
    readOnly: true
  config:
  receivers:
    otlp:
    protocols:
      grpc:
      tls:
        cert_file: /tmp/etc/ssl/certs/my-server-cert/tls.crt
        key_file: /tmp/etc/ssl/certs/my-server-cert/tls.key
        client_ca_file: /tmp/etc/ssl/certs/my-client-cert/ca.crt
  processors: {}
  exporters:
    debug:
    verbosity: normal
    prometheus:
    endpoint: ":8080"
    otlp/jaeger:
    endpoint: "my-open-telemetry-collector.jaeger.svc.cluster.local:4317"
    tls:
      insecure: true
  service:
    pipelines:
    metrics:
      receivers: [otlp]
      processors: []
      exporters: [debug, prometheus]
    traces:
      receivers: [otlp]
      processors: []
      exporters: [debug, otlp/jaeger]
----
マニフェストを適用します：
[source,console]
----
kubectl apply -f otel-collector.yaml
----

その構成は、トレースイベントを受信し、Jaeger に転送するための単純な処理パイプラインを使用します。また、メトリクスを受信し、Prometheus による収集のために公開します。

mTLS を使用して、{admc-short-name} スタックと OpenTelemetry コレクター間の通信を保護します。ただし、例の複雑さを減らすために、OpenTelemetry コレクターと Jaeger 間の通信は保護されていません。

== {admc-short-name} スタックをインストールします

OpenTelemetry コレクターが実行されているときは、通常の方法で {admc-short-name} をデプロイできます。

{admc-short-name} コンポーネントを構成して、イベントとメトリクスを OpenTelemetry コレクターに送信する必要があります。

[source,yaml,subs="attributes+"]
----
# values.yaml
telemetry:
  mode: custom
  metrics: True
  tracing: True
  custom:
  endpoint: "https://my-collector-collector.{admc-namespace}.svc:4317"
  insecure: false
  otelCollectorCertificateSecret: "my-server-cert"
  otelCollectorClientCertificateSecret: "my-client-cert"
----

`otelCollectorCertificateSecret`キーによって参照されるシークレットには、`ca.crt`という名前のエントリが必要です。それは、OpenTelemetry Collectorによって使用される証明書を発行したCAの証明書を保持しています。

`otelCollectorClientCertificateSecret`キーによって参照されるシークレットには、次のエントリが必要です：`tls.crt`および`tls.key`キー。これらは、OpenTelemetry Collectorに対して認証するために{admc-short-name}スタックによって使用されるクライアント証明書とそのキーです。

暗号化やmTLSを使用しない場合は、これらの値を空のままにしてください。

{admc-short-name}スタックをインストールします：

[source,console,subs="attributes+"]
----
helm install --wait \
  --namespace {admc-namespace} \
  --values values.yaml \
  --set global.imagePullSecrets=\{application-collection} \
  --set recommendedPolicies.enabled=True \
  --set recommendedPolicies.defaultPolicyMode=monitor \
  {admc-release} {admc-chart-location}
----

すべてが整いました。

== Jaeger UIの探索

JaegerウェブUIを使用することで、{admc-short-name}によって生成されたトレースイベントを見ることができます。それらは`kubewarden-policy-server`サービスの下にグループ化されています：

image::jaeger-custom-otel-collector.png[Jaegerダッシュボード]

Traefikを使用してJaeger UIにアクセスするには、Traefikサービスのポートフォワードを行ってください：

[source,console]
----
kubectl -n traefik port-forward service/traefik 8080:80
----

ウェブUIは`\http://localhost:8080`でアクセス可能です。

Traefikをバイパスしたい場合は、Jaeger Queryサービスに直接ポートフォワードしてください：

[source,console]
----
kubectl -n jaeger port-forward service/my-open-telemetry-query 16686
----

ウェブUIは`\http://localhost:16686`でアクセス可能です。

== Prometheus UIの探索

ローカルマシンにポートフォワードすることでPrometheus UIにアクセスできます：

[source,console]
----
kubectl port-forward -n prometheus --address 0.0.0.0 svc/prometheus-operated 9090
----

ウェブUIは現在`\http://localhost:9090`でアクセス可能です。
